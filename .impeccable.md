# Impeccable Design Context

## Design Context

### Users
Home-lab / Home Assistant hobbyists browsing GitHub before deciding whether to
install a new Add-on. Technical, self-hosting, privacy-conscious. Evening/
weekend tinkering context, not a work tool. They already know what an Add-on
repository is; the page's job is "what does this detect, does it actually
work, how do I add it" — not educating a general consumer audience.

### Brand Personality
Inherited from the AxeForge kit itself (`~/workspace/axeforging/branding/README.md`):
*"dark, technical, terminal. Precision-tool energy, not startup gloss."*
Heyra's own accent is `#ff3b3b` (alert-red, distinct from the kit's 4 canonical
flavors — same "one custom accent per project" pattern as sibling project
`rsvp-m5`'s terracotta). No mascot/character — the personality comes from a
live-feeling animated event feed and honest, clean diagrams, not illustration.

### Aesthetic Direction
Reference: `axeforging.github.io/rsvp-m5` (cataloged directly, not guessed) —
custom illustration, one purposeful animated centerpiece that demonstrates
the product actually working, layered gradient/shadow/blur depth, sticky nav,
asymmetric responsive grids. Heyra adapts this without the mascot: the
centerpiece is a mocked live event feed (baby_cry/smoke_alarm/etc. detections
scrolling in with a pulse per event) instead of an illustrated demo widget.
Dark theme only (matches the kit, matches the audience's viewing context).
Anti-reference: flat bullet-list sections with no visual hierarchy (the
page's prior state) — that's the thing being fixed.

### Design Principles
1. Show the product working, don't just describe it — the live event feed is
   the hero's job, not a paragraph of bullet points.
2. Every claim stays honest — the mic-range diagram is illustrative and says
   so; nothing implies lab-measured data Heyra doesn't have (Phase 4
   calibration is explicitly not started, see CLAUDE.md).
3. No mascot. Personality comes from motion, diagram clarity, and the accent
   color, not a character.
4. `dog_bark` and every other event gets equal visual weight — no bundling
   two events into one bullet where one becomes easy to miss.
5. Respect `prefers-reduced-motion` on the feed animation (same pattern
   rsvp-m5 already uses for its own centerpiece).
